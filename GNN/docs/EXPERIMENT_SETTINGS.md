# Experiment settings (NVIDIA V100)

> Settings used for every result in `docs/results/` (models RGCN, MAGNN, SlotGAT, SeHGNN, CMPNN, PathNet, PAIN; arms original / universal / augmentation / invariant).

## 0. Hardware, software, determinism

**Every experiment in this document ran on NVIDIA V100-SXM3 32 GB GPUs, one GPU per run.**

| item | value |
|---|---|
| CPU cores / host RAM per job | 4 (8 for the RGCN Freebase/WordNet suite), 16–128 GB as required by the preprocessing |
| software (RGCN, MAGNN, SlotGAT, SeHGNN, PathNet) | Python 3.11, PyTorch 2.4.0+cu124, DGL 2.4.0 (`DGLBACKEND=pytorch`), `torch_sparse` for SeHGNN's Freebase selectors (PathNet needs no DGL) |
| software (PAIN) | Python 3.11, PyTorch 2.13.0+cu126 (`envs/pain.txt`; its deterministic CUDA `cumsum` is unavailable in PyTorch 2.4) |
| software (CMPNN) | Python 3.11 conda env `torchdrug_env`: PyTorch 2.0.1+cu118, torchdrug 0.2.1, torch_scatter 2.1.2; CUDA module 11.7 (JIT extension cache) |
| seeds | 1566911444, 20241017, 20251017 for every cell; every result is mean ± population std (ddof = 0) over the three |
| determinism | `torch.use_deterministic_algorithms(True)`, `CUBLAS_WORKSPACE_CONFIG=:4096:8`, `PYTHONHASHSEED=0`, seeded NumPy/torch/CUDA generators; sorted edge insertion; segment (not atomic) reductions in the RGCN/CMPNN invariant runners; per-(epoch, batch) seeded samplers in MAGNN |
| bitwise claim | one GPU architecture per claim. The invariant arm's τ = 1 is verified as identical per-epoch parameter hashes and identical final checkpoints across the variants of a seed, not as an approximate statistic |
| resumability | every runner checkpoints per epoch (super-epoch for augmentation) with atomic state files; interrupt-and-resume equality was verified bitwise per runner before use |

## 1. Protocol shared by every model and cell

* **Four arms per cell.** *Original*: one model trained and evaluated per dataset variant on its own (physical) graph. *Canonical / universal* (`{model}*`): one model on the union graph of the task's variants. *Data augmentation*: one model trained jointly on all variants' physical graphs (super-epoch = one epoch on every variant in a seeded shuffled order, one shared optimizer), evaluated per variant. *Invariant*: one model per variant on that variant's compiled semantic program (the model-specific instantiation of the transformation-invariant mapping; see per-model rows). Same architecture, loss, optimizer, budget, seeds and evaluation in all four.
* **Selection uses the evaluation metric.** Model selection and early stopping use validation micro-F1 (NC) or validation MRR (LP) — never validation loss (SlotGAT Freebase stops on validation loss but *selects* on validation micro-F1). Augmentation selects on the mean over variants.
* **Supervision is shared.** Splits, labels, positive pairs, negative candidates and batch composition are identical across variants, arms and models (hash-verified per bundle). IMDb node features are the canonical pooled bag-of-words table (`common/imdb_canonical_features.py`) for every model that uses features; DBLP, WN18RR and Freebase are featureless (learned per-type/per-entity embeddings or sparse identity inputs).
* **Link-prediction evaluation.** IMDb: each held-out pair against K = 19 sampled negatives (Movie–Year: frequency-matched years; Movie–Director: uniform directors), tie-aware MRR / Hits@k (averaged rank: 1 + #better + #tied/2). DBLP: every other conference (19 = the full 20-conference candidate set). WN18RR: filtered full-entity ranking for Hits/MRR; 50 fixed seeded negatives per query (`candidate_seed 1566911444`) for the invariance statistic.
* **Query-edge masking in LP training** (CMPNN's `remove_easy_edges` convention, applied identically by MAGNN and by the SlotGAT LP study on IMDb / DBLP via `--mask-batch-edges`; the SlotGAT WN18RR arms leave the target edges in the graph): for a training query (h, t) the edge (h, t)/(t, h), its alias copies (IMDb `link(h)`) and the head's label-derived edges (DBLP `paper_to_area`) are removed from the message graph for the positive **and** every negative candidate, so a training query is scored the way a held-out one is. RGCN's LP runner is transductive (full-graph encoder, no per-query masking).
* **Invariance statistic.** For every pair of variants and every seed: per test node (NC, class-logit vector) or test query (LP, candidate-score vector) Kendall τ-b between the two outputs, averaged over nodes/queries (identical vectors count 1); LP adds τ over the per-query Hit@1 / Hit@3 indicators. Same statistic for the original, augmentation (one model, two input graphs) and invariant arms.
* **Recorded per run.** Task metrics, best/total epochs, training time, parameter count and MiB, peak training and inference GPU memory (`torch.cuda.max_memory_allocated`, separate windows), inference time, first-step audit (init / logits / gradient hashes), checkpoint hash; per-epoch trace with state hashes.
